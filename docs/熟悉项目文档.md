## 一、项目概述

### 1.1 项目简介

JimuReport 一丰报表平台是基于 [JeecgBoot JimuReport](https://github.com/jeecgboot/JimuReport) 二次开发的报表与MCP服务集成项目。主要功能包括：

- **积木报表**：复杂报表设计、打印、图表报表
- **积木BI**：数据大屏、仪表盘可视化
- **MCP工具服务**：订单查询、医保查询、药品查询、下单、订单审核等MCP接口
- **表关联功能**：多表关联查询配置与数据关联

### 1.2 技术栈

| 技术 | 说明 |
|------|------|
| Spring Boot 2.x | 基础框架 |
| MyBatis + MySQL | 数据持久层 |
| SaToken | 身份认证框架 |
| WebSocket + STOMP | 实时消息推送 |
| HikariCP | 数据库连接池 |
| Redis | 缓存和会话（可选） |

## 二、数据源架构

### 2.1 双数据源设计

本项目采用**双数据源架构**，避免报表请求误走海典库：

| 数据源 | 用途 | 配置key |
|--------|------|---------|
| **本地报表库** (jimureport) | 系统自身使用，存储报表配置、API生成器配置、表关联配置等 | `spring.datasource` |
| **海典同步库** (antis_yifengdata_hub) | 业务数据，订单、患者、药品、库存等从海典同步而来 | `haidian.datasource` |

### 2.2 数据源配置（application.yml）

```yaml
# 本地报表库
spring:
  datasource:
    jdbc-url: jdbc:mysql://localhost:3306/jimureport
    username: jimureport
    password: **********

# 海典同步库
haidian:
  datasource:
    jdbc-url: jdbc:mysql://rm-****.mysql.rds.aliyuncs.com:3306/antis_yifengdata_hub
    username: netteam
    password: netteam
```

### 2.3 重要约束

> **在积木报表中使用SQL数据集时，必须选择「海典同步库数据源」**，否则查询不到业务数据。

## 三、MCP接口服务

### 3.1 概述

MCP（Model Context Protocol）接口服务提供标准化工具调用，支持JSON-RPC 2.0规范和传统POST方式。

**MCP服务根地址**：`{服务根地址}/mcp/rpc`

**JSON-RPC调用示例**：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "core_order_query",
    "arguments": {"orderId": "1551015496417349"}
  }
}
```

### 3.2 工具清单

| 工具名称 | 功能 | 数据来源表 |
|----------|------|-----------|
| `core_order_query` | 订单查询 | `corecmsorder` |
| `core_insurance_query` | 医保/患者档案查询 | `corecmsusership` |
| `core_drug_query` | 药品查询 | `t_ware_base` |
| `core_visit_strategy_query` | 回访策略查询 | （预留，当前暂无数据） |
| `core_order_create` | 下单占位 | 调用中台接口 |
| `core_profile_create` | 建档 | `corecmsusership` |
| `core_shipment_create` | 发货登记 | `mcp_shipment_request_log` |

### 3.3 核心接口详解

#### 3.3.1 订单查询（core_order_query）

根据订单号查询订单详情。

**请求**：
```json
POST /mcp/core_order_query
{"orderId": "1551015496417349"}
```

**返回字段**：
| 字段 | 说明 |
|------|------|
| orderId | 订单号 |
| status | 订单状态 |
| payStatus | 支付状态 |
| shipStatus | 配送状态 |
| goodsAmount | 商品总价 |
| orderAmount | 订单实际销售总额 |
| payType/paymentCode | 支付方式 |
| sfwaybillNo | 顺丰运单号 |
| logisticsName | 物流名称 |
| patient/patientIllness | 患者信息 |
| prescriptionDoctor | 开方医生 |

#### 3.3.2 医保查询（core_insurance_query）

根据患者标识查询医保/档案信息。

**请求**：
```json
POST /mcp/core_insurance_query
{"idCard": "320************"}
```

**查询优先级**：userId > idCard > mobile

**返回字段**：
| 字段 | 说明 |
|------|------|
| userId | 海典用户ID |
| name | 患者姓名 |
| mobile | 手机号 |
| idCard | 身份证号 |
| customerId | 医保卡号 |
| relation | 关系（本人/家属） |
| doctor | 责任医生 |
| department | 科室 |
| disease | 病种 |
| pharmacist | 药师 |

#### 3.3.3 药品查询（core_drug_query）

根据名称或条码查询药品信息。

**请求**：
```json
POST /mcp/core_drug_query
{"keyword": "阿莫西林"}
// 或
{"barCode": "6945898600069"}
```

**返回字段**：
| 字段 | 说明 |
|------|------|
| WAREID | 药品ID |
| WARENAME | 药品名称 |
| WAREGENERALNAME | 通用名 |
| WARESPEC | 规格 |
| FACTORYID | 厂家ID |
| WAREUNIT | 单位 |
| FILENO | 批准文号 |
| WAREABC | 拼音码 |
| BARCODE | 条码 |

#### 3.3.4 下单占位（core_order_create）

向中台发起下单请求，双表留痕。

**双表留痕机制**：

| 表名 | 说明 |
|------|------|
| `mcp_order_create_request_log`（表A） | 保存用户传入的原始下单数据 |
| `mcp_order_create_order_log`（表B） | 保存生成的订单数据 + 中台响应 |

**审核状态流转**：
- `0` - 待审核
- `1` - 已通过
- `2` - 已驳回
- `8` - 原始接入留痕（不参与审核列表）

### 3.4 MCP接口目录

| 接口路径 | 说明 |
|----------|------|
| `POST /mcp/rpc` | JSON-RPC 2.0统一入口 |
| `POST /mcp/core_order_query` | 订单查询 |
| `POST /mcp/core_insurance_query` | 医保查询 |
| `POST /mcp/core_drug_query` | 药品查询 |
| `POST /mcp/core_visit_strategy_query` | 回访策略查询 |
| `POST /mcp/core_order_create` | 下单 |
| `POST /mcp/core_profile_create` | 建档 |
| `POST /mcp/core_shipment_create` | 发货登记 |
| `POST /mcp/core_oauth_token` | 获取OAuth token |

## 四、订单审核功能

### 4.1 功能说明

订单审核是MCP下单流程的重要环节，用户通过MCP下单后，需要在审核页面进行审核操作。

### 4.2 访问方式

| 方式 | 地址 |
|------|------|
| 直接访问 | `http://{host}:{port}/mcp/order-audit` |
| 导航访问 | 从任意管理页面（如 `/api-generator/list`）顶部导航栏点击「MCP订单审核」 |

### 4.3 功能列表

- 查看订单列表（按状态筛选）
- 查看患者信息和药品列表
- 审核通过/驳回操作
- 自动刷新（WebSocket实时推送）
- 播放提示音（新订单到达）

### 4.4 审核页面SQL（积木报表）

根据MySQL版本选择对应SQL文件：

| MySQL版本 | SQL文件 |
|-----------|---------|
| 5.7.x | `db/jimureport_mcp_order_request_view_mysql57.sql`（推荐） |
| 5.7.x（简化版） | `db/jimureport_mcp_order_request_view_simple.sql` |
| 8.0.x | `db/jimureport_mcp_order_request_view.sql` |

> **注意**：在积木报表中使用时，**必须选择「海典同步库数据源」**。

## 五、表关联功能

### 5.1 功能说明

表关联功能支持多表关联查询配置，可在积木报表中创建跨表关联的数据集。

### 5.2 核心配置项

```yaml
jmreport:
  table-association:
    # SQL执行超时（秒）
    preview-query-timeout-seconds: 240
    # 预览时对主表最多取多少行
    preview-main-row-cap: 1200
    # 预览时右表LIMIT
    preview-join-side-row-cap: 8000
    # 两侧ORDER BY关联键+LIMIT代替EXISTS/IN
    preview-dual-key-limited-join: true
```

### 5.3 相关文件

| 文件 | 说明 |
|------|------|
| `db/table_association_init.sql` | 初始化脚本 |
| `src/.../TableAssociationController.java` | 控制器 |
| `src/.../TableAssociationServiceImpl.java` | 服务实现 |
| `src/.../mapper/JmTableAssociationMapper.xml` | MyBatis映射 |

## 十三、常见问题排查

### 13.1 订单查询不到数据

1. 确认使用的是**海典同步库数据源**（不是jimureport主库）
2. 确认 `corecmsorder` 表中有数据
3. 检查 `haidian.datasource` 配置是否正确

### 13.2 前端页面"加载失败"

1. 检查后端服务是否启动
2. 检查接口路径是否正确
3. 检查浏览器控制台错误信息
4. 确认跨域配置是否正确

### 13.3 WebSocket推送失败

1. 检查WebSocket配置是否正确
2. 确认STOMP协议配置
3. 查看服务端日志

### 13.4 SQL执行报错

1. 确认MySQL版本（执行 `SELECT VERSION()`）
2. 根据版本选择正确的SQL文件
3. 确认数据源配置正确
